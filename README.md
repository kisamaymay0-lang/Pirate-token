# PirateChestToken

Плагин для Paper/Purpur 1.21.1+ (Java 21). При успешном броске шанса ванильный блок сундука — с его настоящей моделью, текстурой и обычной анимацией крышки — временно покачивается для зрителей, затем открывает инвентарь. Над ним поднимается светящаяся надпись токена с частицами. После анимации сундук разрушается, а оставшееся содержимое выпадает на землю. Сам токен — только визуальная анимация, предмет токена не создаётся.

При неудачном броске сундук открывается обычным образом.

## Требования

- Java 21 (JDK)
- Maven 3.8+
- Paper или совместимое ядро Purpur 1.21.1+

## Сборка и установка

Из корня репозитория выполните:

```bash
mvn clean package
```

Готовый файл: `target/pirate-chest-token-1.0.0.jar`. Скопируйте его в `plugins/` сервера и перезапустите сервер. Paper API имеет scope `provided`, поэтому API сервера не упаковывается внутрь JAR; сторонние библиотеки и shade-плагин не нужны.

## Настройка

При первом запуске плагин создаст `plugins/PirateChestToken/config.yml`:

```yaml
drop-chance: 0.001          # 0.001 = 0.1%; диапазон 0..1
debug: false
title-enabled: true
sound-enabled: true
particle-enabled: true
glow-radius: 30
glow-duration-ticks: 30
shake-duration-ticks: 12
token-animation-ticks: 50
token-name: "🏴‍☠️ Pirate Shop Access"
```

Для гарантированного теста временно выставьте `drop-chance: 1.0`. Шанс `0.01` означает 1%, `0.001` — 0.1%. Настройки применяются после перезапуска сервера.

## Последовательность и ограничение API

Для двойного сундука шанс проверяется один раз на открытие. При выигрыше `InventoryOpenEvent` сначала отменяется, чтобы дать сундуку коротко покачаться; затем исходный сундук открывается стандартным API, и Minecraft показывает свою штатную крышку. При показе токена настоящий сундук ломается и его оставшиеся предметы выбрасываются на землю. Если открывший игрок выходит или закрывает GUI во время анимации, последовательность отменяется, а сундук остаётся на месте.

Paper не предоставляет отдельную сущность «сундук-блок»: модель сундука отрисовывается клиентом как block entity, и `BlockDisplay` с `Material.CHEST` не воспроизводит её. Вагонетка с сундуком действительно использует ванильную модель, но добавляет тележку и выглядит не как парящий обычный сундук. Поэтому плагин оставляет сам настоящий блок на месте и использует временную клиентскую смену его направления как приближение к дрожанию. Для гладкого свободного движения именно модели сундука нужна клиентская модель из ресурспака/мода.
