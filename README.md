# PirateChestToken

Небольшой плагин для Paper/Purpur 1.21.1+ (Java 21): при открытии обычного или запертого (trapped) сундука с заданной вероятностью игрок получает предмет-токен «Токен Пиратского Магазина» и ванильные эффекты.

## Требования

- Java 21 (JDK)
- Maven 3.8+
- Paper или совместимое ядро Purpur 1.21.1+

## Сборка

Из корня репозитория выполните:

```bash
mvn clean package
```

Готовый плагин появится по пути `target/pirate-chest-token-1.0.0.jar`. Скопируйте этот JAR в каталог `plugins/` сервера и перезапустите сервер. Paper API имеет scope `provided`, поэтому API сервера не упаковывается внутрь JAR; сторонние библиотеки и shade-плагин здесь не нужны.

## Настройка

При первом запуске плагин создаст `plugins/PirateChestToken/config.yml`. Основные параметры:

```yaml
drop-chance: 0.001          # 0.001 = 0.1%; допустимый диапазон от 0 до 1
debug: false
title-enabled: true
sound-enabled: true
particle-enabled: true
glow-radius: 30
glow-duration-ticks: 30
remove-chest-for-others: true
token-name: "🏴‍☠️ Pirate Shop Access"
```

Шанс задаётся дробью: `0.01` — 1%, `0.001` — 0.1%, `1.0` — 100%. После изменения конфигурации перезапустите сервер, чтобы применить настройки.

Токен — предмет бумаги с заданным именем, описанием и внутренней меткой PersistentDataContainer. Сам плагин не подключает магазин и не реализует обмен токена; эту метку можно использовать для интеграции с другим плагином.

## Как работает обработка сундуков

Используется `InventoryOpenEvent`, потому что он срабатывает при фактическом открытии инвентаря и уже предоставляет его holder. Это позволяет не считать клики по сундуку, которые не привели к открытию. Инвентарь двойного сундука представляет собой один открываемый инвентарь, поэтому шанс проверяется один раз на событие; обе половины при этом находятся для визуальных эффектов.

При выигрыше токен выпадает около игрока, а владелец получает заголовок на три секунды, сообщение в action bar, звук повышения уровня и частицы тотема. Невидимая светящаяся стойка для брони показывается другим игрокам только в радиусе `glow-radius` и удаляется через `glow-duration-ticks`. Если `remove-chest-for-others` включён, этим же игрокам клиент временно получает подмену сундука на воздух; по окончании эффекта плагин отправляет клиентам актуальные данные блока. Владельцу подмена не отправляется, а реальный блок мира никогда не меняется.

Подмена реализована через `Player.sendBlockChange`, а не `block.setType(Material.AIR)`: `sendBlockChange` меняет только отображение конкретного клиента. Изменение настоящего блока уничтожило бы сундук для всех, могло бы потерять содержимое и повредить двойной сундук. При восстановлении проверяется текущий блок, так что легально сломанный или заменённый сундук не «восстанавливается» плагином.

## Ограничение визуального эффекта

Без ресурспака сервер не может заставить сам блок-сундук получить полноценный эффект контура свечения (glowing outline), так как ванильный glow — это эффект сущности. Здесь используется невидимая marker-стойка с эффектом свечения как серверный компромисс; контур будет иметь форму стойки и не является точным контуром сундука. Для точного свечения самого сундука нужен клиентский ресурспак/мод либо иной визуальный эффект, например частицы вокруг блока. Звук, частицы и текстовые компоненты используются из ванильной игры и не требуют ресурспака.
